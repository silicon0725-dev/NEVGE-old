# Task 0008.7.3 — Scratch Adapter Boundary Stabilization

## Status

Implemented on top of `0008.7.2.2` and `EXT-0001`.

Scene System version: `0.7.3`

## Problem

The previous adapter used `ngvge.scratch-sprite-node` as both the semantic Runtime Node type and the Scratch binding representation. Project Explorer also identified ownership by checking that backend-specific type ID.

This made the Scratch implementation part of the semantic node identity and allowed generic Runtime mutation paths to bypass Target and Sidecar ownership cleanup.

## New ownership model

```text
ngvge.sprite-node                 Semantic owner
└── ngvge.scratch-target-binding Compatibility component
```

`ngvge.sprite-node` is now a hidden semantic Runtime Node type registered by the Runtime Node Model. It contains no Scratch Target, Renderer object or backend handle.

`ngvge.scratch-sprite-node` remains only as a legacy migration type.

## Implemented changes

### Semantic node migration

- Added `SpriteRuntimeNode` under `src/lib/runtime-nodes`.
- Added `SEMANTIC_RUNTIME_NODE_TYPE_IDS.SPRITE`.
- Registered hidden `ngvge.sprite-node` as a built-in semantic node type.
- Legacy `ngvge.scratch-sprite-node` records migrate through Runtime state import.
- Migration preserves NodeId, BindingId, components, parent and descendants.

### Binding schema v2

- Adapter capability version is now 2.
- Sidecar schema version is now 2.
- Added explicit `destroyPolicy` with `delete-target` and `detach` values.
- Version 1 records default to `delete-target` and upgrade during the next write.
- Binding components include `adapterType`, lifecycle and schema metadata.

### Scene-scoped target indexing

Volatile target indexes now use:

```text
SceneId + targetRuntimeId
```

Public target lookup accepts an optional SceneId and otherwise resolves against the active scene.

### Ownership deletion

- Added `destroyBindingByNodeId()`.
- Project Explorer routes bound Sprite deletion through the Adapter.
- Direct Runtime Node deletion is intercepted by the Adapter lifecycle listener.
- Target, Sidecar, binding indexes, semantic node and Runtime child subtree are removed consistently.
- Adapter-owned node destruction uses a recursion guard.

### Editor projection

- Added `createScratchSpriteTreeProjection()`.
- Project Explorer associates bindings by NodeId rather than node type.
- Raw Scratch sprite rows are hidden only when a valid semantic owner node exists.
- Scratch-bound nodes display as semantic `Sprite` rows with `Scratch · Bound/offline` status.
- Runtime rename, duplicate and enabled-state actions are disabled for Scratch-authoritative Sprite nodes.

## Compatibility

Existing projects using:

```text
ngvge.scratch-sprite-node
scratchSpriteBindings schemaVersion 1
```

are migrated automatically. Stable identities are retained.

The old `SCRATCH_SPRITE_NODE_TYPE_ID` export remains as a deprecated alias for migration callers. New code must use `SPRITE_NODE_TYPE_ID` and detect Scratch ownership through the binding component/capability.

## Validation targets

- One Project Explorer row per original Scratch Sprite.
- No backend-specific node type required for editor projection.
- Childless Sprite rows have no disclosure control.
- Scene A and Scene B bindings remain isolated.
- Deleting a bound semantic node removes its Target and Runtime subtree.
- Direct Runtime deletion cannot leave an orphan Sidecar.
- Legacy type and schema migration retain stable identity.
- Volatile target IDs are absent from persistent records.
