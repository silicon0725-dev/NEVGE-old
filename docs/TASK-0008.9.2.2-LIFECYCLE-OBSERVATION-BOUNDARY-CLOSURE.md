Portable Runtime Node Capability: `ngvge.runtime-node-model@1.2`

## Purpose

This closure seals the two remaining paths that could bypass the lifecycle execution boundary:

1. lifecycle Hooks receiving writable live Runtime objects;
2. public Capability observers synchronously mutating the semantic graph while an event is being dispatched.

No project persistence schema or portable public method surface changes in this task.

## Hook observation boundary

Lifecycle Hooks no longer receive `RuntimeNodeGraph`, `RuntimeNode`, or `RuntimeComponent` instances.

The Hook context contains:

```text
runtimeGeneration
sequence
phase / reason / fromState / toState
nodeId / componentId
node       detached deep-frozen Plain Data snapshot
component  detached deep-frozen Plain Data snapshot or null
query      read-only Runtime query facade
resources  provider-owned local resource context
```

The query facade exposes only:

```text
getNodeSnapshot
getComponentSnapshot
getSceneSnapshot
querySubtree
```

It has no mutation, persistence, registration, subscription, Backend, or graph access.

Provider resources are local-only and are not project data, lifecycle event payloads, or Runtime semantic state.

## Public Observer execution boundary

Every callback registered through `runtimeNodeModel.subscribe()` executes inside the shared lifecycle execution guard.

A synchronous semantic mutation from an observer is rejected with:

```text
RUNTIME_LIFECYCLE_REENTRANT_MUTATION
originKind = observer
```

Portable Mutation methods return:

```text
applied = false
persisted = false
snapshot = null
error.details.eventType
error.details.runtimeGeneration
error.details.sequence
```

The rejection is recorded by `observerReentrantMutationCount`. It is not recursively emitted as another lifecycle error event from the same dispatch stack.

Observer callbacks remain isolated: one rejected mutation or thrown observer error does not prevent later observers from receiving the original event, and does not interrupt the outer lifecycle transition.

## Guard release

Hook and Observer guard contexts use `try/finally`. Once the callback returns or throws, later Commands execute normally.

## Persistence isolation

Hook snapshots, query facades, resource contexts, observer guard state, and diagnostics are Runtime-only. They do not enter Runtime Node persistent records or Scene project extension data.
