# Task-0007.3.1 — Extension Hub Architecture

## Goal

Introduce a stable data layer for the future NGVGE Extension Hub without removing or rewriting the existing online extension galleries.

## Added architecture

- `ExtensionSourceRegistry`: registers local, compatibility, and remote marketplace providers.
- `ExtensionRegistry`: indexes normalized extension manifests.
- Manifest v2 adapter for current Scratch/TurboWarp-style gallery items.
- Built-in provider definitions for NGVGE, Scratch, 02Engine, TurboWarp, PenguinMod, Mist, SharkPool, AstraEditor, CCW, and Other.
- Source grouping metadata: local, online, compatibility, and system.

## Compatibility

The existing gallery fetch and import flow remains active. The new layer wraps current gallery entries instead of replacing them. Existing URLs and source-specific processors remain in `extension-library.jsx`.

## First-party migration

`NGVGE Camera V2` and `NGVGE XY Stretch` now use the `ngvge` source tag, so they can be separated from compatibility extensions in the next UI milestone.

## Non-goals

- No new Extension Hub visual design yet.
- No installer, updater, account, marketplace server, or permission dialog yet.
- No removal of legacy providers.
