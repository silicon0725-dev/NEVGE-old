# Task-0007.2 — Node Tree Foundation

## User-visible goal

Project Explorer can create NGVGE nodes at the scene root or below a selected parent. The initial built-in node types are:

- `Node2D`
- `PhysicsBody2D`
- `Collider2D`
- `Marker2D`

Stage and Sprite targets remain normal Scratch targets. NGVGE child nodes are project metadata attached to the target hierarchy.

## Editor workflow

1. Expand `Project → Entities`.
2. Choose a node type and an optional name.
3. Use `+ Root Node` to create a top-level NGVGE node.
4. Select a Stage, Sprite, or compatible NGVGE node.
5. Use `+ Child Node` to create below the selected parent.
6. Select the node to edit it in Inspector.

When a child node belongs to a Sprite, selecting it keeps that Sprite as the active Scratch editing target while Inspector displays the child node.

## Data model

Each project node has a stable logical ID:

```json
{
  "id": "node:uuid",
  "typeId": "ngvge.collider2d",
  "name": "Hitbox",
  "parentId": "node:parent",
  "childIds": [],
  "enabled": true,
  "properties": {
    "shape": "rectangle",
    "width": 48,
    "height": 48
  }
}
```

Target-backed Stage and Sprite nodes are stored in the same hierarchy, but remain bound to ordinary Scratch VM targets.

## Persistence

The hierarchy is serialized as the hidden project section `ngvge-node-tree` through the existing additive `ngvge.projectSections` persistence layer.

Target node bindings are saved by original-target order so the hierarchy can reconnect even when Scratch VM generates different runtime target IDs after loading.

Normal Scratch target, block, costume, and sound data is unchanged.

## Undo and Redo

The following operations use the shared Task-0005 property history:

- create node;
- rename node;
- enable or disable node;
- edit node properties;
- reparent node through the database API;
- delete a node subtree.

## Plugin preparation

Node types are defined by `ngvgeNodeTypeRegistry`. A future editor plugin can register a type without modifying Project Explorer:

```js
context.nodes.registerType({
    id: 'plugin.example.wind-zone',
    label: 'WindZone2D',
    category: 'Physics',
    icon: 'W',
    pluginId: 'plugin.example',
    defaults: {strength: 1},
    fields: [
        {id: 'strength', label: 'Strength', type: 'number'}
    ]
});
```

If a project contains a plugin node while its plugin is unavailable, the unknown node and its raw properties remain preserved.

## Current runtime boundary

`PhysicsBody2D` and `Collider2D` are editable data nodes in this milestone. They do not yet run a physics simulation or draw collision debug shapes. Runtime behavior will be supplied by the later component, physics, and plugin-host milestones.

## Compatibility

- Scratch / TurboWarp / 02Engine: ordinary targets continue to work.
- SB3: NGVGE node metadata is additive; external editors may ignore or strip it when re-saving.
- NGVGE: hierarchy and node properties are restored.
- Plugins: node-type registry is ready for a future Plugin Context adapter.
