# Task-0007.2.4 — Context Menu Click Fix

## Problem

The Project Explorer node context menus opened correctly, but every menu button appeared inert.

## Root cause

The menu installed an unconditional native `document.pointerdown` listener to close itself. The project uses React 16, where synthetic pointer/click events are delegated at document level. Pressing a menu button therefore caused the native document listener to unmount the portal before the button's later `click` handler could run.

## Fix

- Add a shared `useDismissableContextMenu` hook.
- Keep a ref to the portal menu element.
- Close only when the native pointer target is outside the menu.
- Register the outside-pointer listener in capture phase so it is deterministic across windows and portals.
- Execute the selected command before requesting menu closure.
- Add Escape-key dismissal.
- Prevent a second context menu from opening inside the menu surface.

## Affected menus

- Entity/root context menu
- Node context menu

## Expected behavior

- `Add Node` opens the searchable node dialog.
- `Add Child Node` opens the searchable node dialog with the selected parent retained.
- Rename, Duplicate, Enable/Disable, Reparent, Expand, Collapse, and Delete execute normally.
- Clicking outside, scrolling, pressing Escape, or blurring the window closes the menu.
