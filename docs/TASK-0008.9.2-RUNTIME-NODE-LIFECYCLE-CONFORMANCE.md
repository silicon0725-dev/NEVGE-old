# TASK 0008.9.2 — Runtime Node Lifecycle Conformance

Status: Implemented / Lifecycle Contract Frozen by `0008.9.2.2`  
Parent: `0008.9 Runtime Node Model Freeze`  
Depends on: `0008.9.1.1 Runtime Node Public Boundary Cleanup`  
Scene System version: `0.8.9.2.2`  
Runtime Node persistent format: `1`  
Runtime Node public API: `ngvge.runtime-node-model@1.2`  
Lifecycle Contract: `ngvge.runtime-node-lifecycle@1`

## Purpose

This task freezes the observable Runtime Node and Runtime Component lifecycle without changing the already-frozen portable API surface or project persistence format.

It defines:

- legal lifecycle states and transitions;
- Ready, activation, Reparent and Reorder semantics;
- Component ownership behavior;
- child-first destruction order;
- normalized lifecycle events;
- local Hook failure isolation;
- observer failure isolation;
- persistence exclusion for all derived lifecycle state.

## Canonical state machines

Node:

```text
Created → Attached → Ready → Active / Disabled
                               ↓
                            Detached
                               ↓
                            Destroyed
```

Component:

```text
Created → Attached → Ready → Active / Disabled
                               ↓
                            Detached
                               ↓
                            Destroyed
```

The machine-readable transition tables are exported by `runtime-node-lifecycle.js`. Invalid transitions throw `RUNTIME_LIFECYCLE_TRANSITION_INVALID`.

Roots are a deliberate special case: Global Root and Scene Root can move from `created` directly to `ready`, because they have no semantic parent. They then enter `active` or `disabled` according to scope activation.

## Ready semantics

`Ready` is one-shot per Runtime instance.

```text
Create and first Attach:
create → attach → ready → enable-or-disable

Reparent:
disable → detach → attach → enable-or-disable
```

Reparent does not repeat Node Ready.

Before the reparented Node emits `detach`, its currently active descendant subtree is disabled. This prevents observers from seeing an attached child remain active beneath a detached ancestor.

Owned Components retain the same `ownerId` during Node Reparent. They only follow activation:

```text
component:disable → component:enable
```

They do not receive:

```text
component:detach
component:attach
component:ready
```

## Reorder semantics

Moving a Node to another index under the same parent emits only:

```text
reorder
```

It does not:

- change parent identity;
- change lifecycle state;
- emit detach or attach;
- repeat ready;
- affect Component ownership.

## Activation semantics

`enabledSelf` is authored state. `activeInHierarchy` is derived state.

```text
activeInHierarchy = enabledSelf && parent.activeInHierarchy
```

Roots derive activity from scope:

- Global Root is active;
- the selected Scene Root is active;
- other Scene Roots are disabled but remain loaded.

Activation propagation order is frozen:

```text
Enable:
Node enable → Component enable → descendants

Disable:
Component disable → Node disable → descendants
```

A disabled Component remains owned and Ready. Re-enabling it does not repeat Attach or Ready.

## Destroy order

Subtree destruction is child-first.

For each non-root Node:

```text
1. Destroy descendants
2. Disable active Components
3. Disable Node
4. Detach Node from parent
5. Detach Components from owner
6. Destroy Components
7. Destroy Node
8. Remove Node identity from active Runtime graph
```

This guarantees that Component cleanup occurs while the owner Node still has a valid stable identity and before that identity is removed from the active graph.

`dispose()` is idempotent. A second disposal call is a no-op.

## Local Hook policy

Lifecycle Hooks are Local Provider Bindings. They are not portable Commands, Queries or protocol callbacks.

Supported phases:

```text
onCreate
onAttach
onReady
onEnable
onDisable
onDetach
onReorder
onDestroy
```

Frozen Hook error policy:

```text
isolate-and-report
```

A Hook exception:

- does not veto the lifecycle transition;
- does not roll the Graph back to an intermediate state;
- does not interrupt descendant or Component cleanup;
- emits a normalized `lifecycle:error` event;
- increments `lifecycleHookErrorCount`.

Constructors and local Provider factories remain authoritative construction boundaries. A constructor/factory exception still prevents Node creation before lifecycle ownership is established.

## Event contract

Lifecycle transitions emit portable plain-data events through the existing subscription channel:

```js
{
    type: 'lifecycle',
    lifecycleContractVersion: '1',
    runtimeGeneration: 3,
    sequence: 42,
    entityKind: 'node',
    phase: 'attach',
    nodeId: 'node-player',
    componentId: null,
    fromState: 'created',
    toState: 'attached',
    parentId: 'runtime-node:scene-root:scene-a',
    previousParentId: null,
    reason: 'attach'
}
```

Hook errors emit:

```js
{
    type: 'lifecycle:error',
    lifecycleContractVersion: '1',
    runtimeGeneration,
    sequence,
    entityKind,
    phase,
    hookName,
    nodeId,
    componentId,
    state,
    code,
    error
}
```

Events contain no Node instance, Component instance, Scratch Target, Backend Handle, callback or mutable Graph reference.

`(runtimeGeneration, sequence)` is the lifecycle ordering identity. `sequence` is monotonic within one committed Runtime generation. Successful Runtime Graph replacement increments `runtimeGeneration`, resets `sequence`, discards Shadow Graph Trace and publishes `runtime:replaced` as sequence 1. Debug Trace retention is bounded to the latest 512 lifecycle records.

## Observer isolation

Lifecycle and Runtime change subscribers are observers. A subscriber exception:

- cannot veto a mutation;
- cannot interrupt other subscribers;
- cannot interrupt lifecycle cleanup;
- is counted as `graphListenerErrorCount` for Graph listeners or `observerErrorCount` for public Capability subscribers; `listenerErrorCount` is their sum.

Future Engine Protocol Event Subscription must preserve this observer-only semantic.

## Reentrancy and detach closure

Lifecycle Hooks may read Runtime state and manage provider-owned external resources, but synchronous Runtime semantic Graph mutation is rejected with `RUNTIME_LIFECYCLE_REENTRANT_MUTATION`. The error is isolated as `lifecycle:error` and the original transition completes. Implicit deferred mutation is intentionally not part of Lifecycle v1.

Same-state transitions are side-effect-free no-ops before Hook invocation, Trace append or sequence increment. First attachment cannot skip Ready. A previously Ready Node may use the conditional Attached → Active/Disabled edge only while reattaching during Reparent.

Node detach removes the hierarchy relationship. Component detach removes Component ownership. `detachNode()` does not emit `component:detach` and does not clear `component.ownerId`.

## Persistence contract

The following fields remain Runtime-only:

```text
state
activeInHierarchy
Ready invocation flags
Lifecycle Trace
Lifecycle sequence
Hook error counters
Listener error counters
Hook functions
```

Persistent Node and Component records continue to contain only semantic identity, hierarchy, enabled authoring state and persistent data. The persistent format remains version `1`.

On project restore, lifecycle state is reconstructed from semantic records and current Scene activation. It is never trusted from serialized `state` or `activeInHierarchy` fields.

## Machine-readable contract

`getApiContract()` now includes:

```js
{
    lifecycleContract: {
        contractVersion: '1',
        nodeStates,
        componentStates,
        nodeTransitions,
        componentTransitions,
        readySemantics: 'once-per-instance',
        hookErrorPolicy: 'isolate-and-report',
        hookPortability: 'local-provider-only',
        destroyOrder,
        reparentSemantics,
        reorderSemantics
    }
}
```

This adds no method to the frozen public surface. `Reflect.ownKeys(runtimeNodeModel)` remains unchanged from `0008.9.1.1`.

## Validation gates

The task adds:

```text
scripts/validate-ngvge-task-0008.9.2.js
test/unit/lib/runtime-nodes/runtime-node-lifecycle-conformance.test.js
```

The validation covers:

- canonical Node and Component creation sequences;
- detached construction followed by first Attach;
- Ready exactly once;
- Reparent lifecycle order;
- descendant disable before ancestor detach;
- no Component ownership churn during Reparent;
- Reorder without lifecycle restart;
- Scene activation disable/enable propagation;
- inactive Scene creation and restore;
- child-first subtree destruction;
- Component destruction before Node destruction;
- Hook exception isolation;
- subscriber exception isolation;
- invalid transition rejection;
- lifecycle DTO portability;
- bounded 512-record lifecycle Trace retention;
- derived-state persistence exclusion;
- rejection of serialized lifecycle state as authority during restore;
- idempotent disposal;
- all previous 0008.7.3, 0008.8, 0008.9.1 and 0008.9.1.1 regressions.

## Non-goals

- Component Schema and migration rules;
- Component Type Registry ownership;
- full transactional rollback for mutations;
- module-wide Install/Enable/Disable lifecycle;
- Runtime scheduler phases;
- Native ABI callbacks;
- Engine Protocol transport.

Those remain for `0008.9.3`, later Runtime tasks and ARC-C001.
