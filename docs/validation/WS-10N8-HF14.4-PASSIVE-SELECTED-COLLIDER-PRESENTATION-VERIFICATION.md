## Important behavioral checks

A 34-point batch projection resolves the child→parent hierarchy only once for the batch instead of once per point.

A selected-node `collision:refresh` with exactly one matching `changedNodeId` schedules one presentation frame, reads only the selected Collider, updates the selected SVG directly, and does not increase `getDebugViewportSnapshot()` calls.

Area/overlap visualization, unknown/multi-node refreshes and unsafe presentation cases retain the full reconciliation fallback.

## Browser re-test procedure

1. Apply HF14.4 over HF14.3.
2. Rebuild/restart the editor runtime used for the performance test.
3. Confirm `diagnosticsVersion: WS-10N8-HF14.4`.
4. Use the same Circle/Capsule physics scene.
5. Capture once unselected and once while the Collider/RigidBody node remains selected.
6. Compare average FPS, frame P95/P99, LoAF, Collision Prepare and selected-presentation counters/categories.

HF14.4 is not browser-certified until the selected-state regression is materially reduced.
