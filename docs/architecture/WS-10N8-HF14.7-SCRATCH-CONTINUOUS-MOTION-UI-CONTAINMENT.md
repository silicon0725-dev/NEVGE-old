# WS-10N8-HF14.7 | Scratch Continuous-Motion UI Fanout Containment

Status: MACHINE VERIFIED / BROWSER RE-TEST REQUIRED

## Problem

A Scratch loop such as `forever -> go to mouse-pointer` changes the Scratch target transform every VM step. Scratch correctly marks the target dirty and emits `TARGETS_UPDATE/targetsUpdate`, but editor-facing subscribers were treating every position-only update like a full target/UI/topology mutation.

This produced synchronous work inside the Scratch VM timer callback: target serialization + Redux target-list replacement, Project Inspector refresh, and Node Database target synchronization. These tasks are presentation/topology concerns and are not part of Scratch execution authority.

## Decision

Preserve full-rate Scratch execution and Scratch -> NGVGE Transform projection, but contain editor fanout:

- Scratch target motion remains full-rate.
- Scratch renderer remains full-rate.
- Scratch -> NGVGE Transform projection remains signal-driven and phase-coalesced.
- GUI target-list serialization/Redux sync is sampled at ~12 Hz only while Scratch threads are active and topology is unchanged.
- Project Inspector target telemetry is sampled at ~12 Hz during active Scratch execution.
- Node Database `syncTargets()` runs only when the original-target topology signature changes (id/stage/name), not when x/y/direction/size churns.
- Idle/editor mutations remain immediate.

## Authority

No execution state is moved into React/Redux. Redux and Inspector are presentation mirrors only. Node Database remains topology authority for editor nodes and still synchronizes immediately when target topology changes.
