# WS-10N8-HF14.4｜Passive Selected Collider Presentation Fast Path

Status: Implemented / Machine Verified / Browser Re-test Required
Parent: WS-10N8 Physics2D Backend PoC
Depends on: HF14.3 Physics Fixed-Step Backlog Containment & Profiler Store Unification

## Problem

HF14.3 made runtime physics substantially smoother, but keeping a moving Collider2D selected still caused a large editor-only performance regression. The selected-state browser capture reported ~16.47 FPS with frame P50 ~83.3 ms even though Physics2D/Character Collision Query profiler categories were not the visible top offender.

The remaining cost came from editor presentation fanout rather than collision authority:

1. Collider Runtime transform refresh invalidated the full Collider2D debug snapshot.
2. `Collider2DGizmo` rebuilt all visible gizmos and reconciled the selected SVG through React.
3. Circle/Capsule world-point projection resolved the same Transform2D hierarchy once per point (32/34 times).
4. Project Inspector re-rendered at runtime Transform/Physics frequency while a node was selected.

## Architecture decision

Selection visualization is presentation state. It must not force semantic/runtime recomputation when the underlying authority already changed correctly.

HF14.4 therefore preserves all NGVGE Collider2D / Transform2D / Physics2D authority and changes only the editor presentation path.

## Changes

### 1. Batch Transform2D hierarchy projection

`projectPointsThroughHierarchy()` resolves the owner-to-root hierarchy once per point batch and reuses it for every point.

Before:

- Circle: roughly 32 hierarchy resolutions per geometry projection.
- Capsule: roughly 34 hierarchy resolutions.

After:

- Any point count: one hierarchy resolution per batch.

No tessellation precision changes are made.

### 2. Changed-node attribution for Collider Runtime refresh

Collider Runtime refresh batching records `changedNodeIds` from Transform2D runtime changes and includes them in `collision:refresh` events.

This allows presentation consumers to prove that a refresh affects exactly one selected node before bypassing global reconciliation. Unknown, multi-node, topology, camera, preference, or overlap-state changes continue through the full path.

### 3. Passive selected Collider DOM fast path

For a safe `collision:refresh` affecting only the selected node:

- do not increment the global collider revision;
- do not rebuild the full debug viewport snapshot;
- coalesce to one presentation rAF;
- query only `getCollider(selectedNodeId)`;
- update the existing selected SVG group directly using the HF11 DOM presentation path.

Full React/debug-snapshot fallback remains available if the DOM group or selected Collider cannot be materialized safely.

Overlap highlighting disables this shortcut because another Collider's visual state may need to change.

### 4. Project Inspector runtime telemetry containment

The Inspector no longer performs duplicate full renders for `physics:step` plus the corresponding Transform2D `runtime:patch`.

High-frequency `runtime:patch` telemetry is sampled at approximately 12 Hz (83 ms) while authoritative editor/persistent mutations such as commit/attach/detach/rehydrate remain immediate.

Pure `collision:refresh` geometry events do not force Inspector reconciliation; persistent Collider edits and Area enter/exit events remain covered by their authoritative subscriptions/events.

## Authority and compatibility

HF14.4 does not change:

- Collider2D Schema or serialized representation;
- Transform2D runtime authority;
- Physics2D backend semantics;
- Rapier shape-aware primitive mapping;
- collision layer/mask behavior;
- Area2D enter/exit semantics;
- Circle fallback tessellation (32 segments);
- Capsule fallback arc tessellation (16 segments);
- HF11 transient authoring DOM fast path.

## Browser gate

A valid HF14.4 report must show:

- `diagnosticsVersion = WS-10N8-HF14.4`;
- selected moving Circle/Capsule tested under the same runtime conditions as HF14.3;
- `Collider Selected Presentation` at low single-digit milliseconds or lower;
- `colliderSelectedDirectDom > 0` during passive selected motion;
- `colliderSelectedReactFallback` near zero;
- reduced `Collision Prepare` call frequency/cost while selected;
- materially improved selected-state FPS/frame P95 versus the HF14.3 selected baseline.

N8 remains NOT FROZEN until browser evidence passes.
