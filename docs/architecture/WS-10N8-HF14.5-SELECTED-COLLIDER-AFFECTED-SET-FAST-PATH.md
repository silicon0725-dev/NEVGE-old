# WS-10N8-HF14.5 | Exact Affected-Collider Attribution for Passive Selection

## Status

IMPLEMENTED / MACHINE VERIFIED / BROWSER RE-TEST REQUIRED

## Problem

HF14.4 reduced the selected-moving-Collider browser case from ~16.47 FPS to ~49.83 FPS, but browser evidence still showed `Collider Selected Presentation = 0` while `Collision Prepare` and `React Overlays` continued at nearly identical cadence. The passive DOM path was therefore not consistently being admitted.

The HF14.4 admission proof compared raw changed Transform node IDs with the selected Collider node ID. That is insufficient when a parent RigidBody/Transform2D drives a child Collider.

## Design

Collider Runtime maintains a cached reverse dependency index from Transform node ID to the Collider node IDs whose world geometry depends on that Transform. A Transform refresh now carries both:

- `changedNodeIds`: raw Transform nodes that changed;
- `affectedColliderNodeIds`: actual Collider nodes whose world geometry changed.

Physics writeback batching coalesces both sets.

Stage passive selected presentation is admitted only when `affectedColliderNodeIds` proves that exactly one Collider changed and it is the selected Collider. Unknown, multi-Collider, overlap-state, authoring and unsafe cases retain the full React/debug-snapshot path.

## Architecture Boundary

This is presentation attribution only. It does not change Collider2D schema, Transform2D authority, Physics2D semantics, Rapier shape mapping, persistence, Area2D semantics, collision filtering, or tessellation fallback precision.
