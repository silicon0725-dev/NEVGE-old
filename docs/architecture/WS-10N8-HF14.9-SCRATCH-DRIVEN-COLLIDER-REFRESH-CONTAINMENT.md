# WS-10N8-HF14.9 | Scratch-Driven Collider Refresh Containment

Status: IMPLEMENTED / MACHINE VERIFIED / BROWSER RE-TEST REQUIRED

## Problem

HF14.8 removed most mouse-layout and target/toolbox UI churn, but a `repeat -> go to mouse-pointer` stress case with a Collider still caused repeated `collision:refresh` fanout. A transform-only change of a small native Collider set could invalidate the full Stage debug viewport snapshot and React presentation even though only one dynamic debug shape moved.

## Decision

NGVGE Runtime collision semantics remain full-rate. Editor collision debug presentation is separated from Runtime authority:

- exact `affectedColliderNodeIds` remain the admission proof;
- selected Collider presentation continues to use the HF14.5 direct DOM path;
- non-selected transform-only native Collider changes use a sampled direct Canvas path;
- passive dynamic debug presentation is capped at 20 Hz and frame-coalesced;
- the fast path reads only `getCollider(affectedNodeId)` and reuses the existing static/debug list;
- Contacts/overlap state, transform preview, large/unknown affected sets and other semantic changes retain the full snapshot/React fallback.

Static TileMap collision projections remain governed by HF14.6 and are not rebuilt by the dynamic path.

## Authority Boundary

Full-rate and authoritative:
- Scratch VM execution;
- Scratch -> NGVGE Transform projection;
- Collider2D Runtime geometry revision and collision semantics;
- Rapier/Physics execution;
- Area/Sensor transitions.

Sampled editor-only presentation:
- non-selected collision debug Canvas for transform-only motion.
